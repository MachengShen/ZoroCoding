# ZoroCoding macOS 第一版设计规格

日期：2026-07-28
状态：已完成产品界面与架构确认，等待书面规格复核

## 1. 产品定义

ZoroCoding 是一款面向 macOS 的本地编程代理桌面应用。它保留 Codex 日常使用频率最高的核心链路：

1. 选择一个本地项目。
2. 发起自然语言任务。
3. AI 分解任务并显示真实步骤、进度与预计剩余时间。
4. AI 在受控权限内读取和修改文件、运行终端命令。
5. 用户查看执行记录、文件差异、终端输出与最终结果。
6. 用户可暂停、继续、取消、重试或恢复历史任务。

产品名称固定为 **ZoroCoding**。第一版仅支持 macOS 桌面端，不提供 Web 端、移动端或多人协作服务。

## 2. 第一版目标

- 提供可日常使用的本地编码代理，而不是仅能聊天的模型客户端。
- 采用用户确认的「Codex 工作台」三栏布局。
- 将 KIMI K3 作为内置默认模型，通过 Moonshot/Kimi 官方 API 调用。
- 支持添加、测试、编辑和删除其他 OpenAI 兼容模型 API。
- 让任务进度与倒计时由真实步骤状态驱动，而不是播放固定动画。
- 默认在所选项目内自动执行常规读写与命令，对高风险动作强制确认。
- 将任务、消息、步骤和执行事件保存在本机，将 API 密钥交由 macOS 钥匙串保护。

## 3. 非目标

第一版不包含以下能力：

- 云端任务同步、团队账号、多人协作和远程共享。
- Windows、Linux、iOS、Android 或浏览器版本。
- 远程 SSH 工作区、容器编排或云端开发环境。
- 插件市场、MCP 管理中心、自动化定时任务和 GitHub PR 发布流程。
- 本地运行 KIMI K3 模型权重。
- 同时并行执行多个代理任务。任务可排队，但每个应用实例同一时间只执行一个高权限任务。

## 4. 技术路线

采用用户确认的方案：

- **桌面外壳：** Electron
- **界面：** React + TypeScript
- **构建：** Vite
- **本地代理运行时：** Electron 主进程中的 TypeScript 模块
- **进程间通信：** 通过受控 preload bridge 暴露的类型化 IPC
- **任务存储：** 本地 SQLite
- **密钥存储：** Electron `safeStorage` 使用的 macOS 钥匙串能力；数据库只保存密钥引用和脱敏信息
- **终端：** 主进程创建并管理带项目工作目录的 shell 子进程，向界面流式发送输出
- **发布形态：** macOS `.app` 与 `.dmg`。开发版本先完成本地打包；正式分发再加入签名与公证。

### 4.1 进程边界

React 渲染进程只负责显示和用户输入，不直接访问 Node.js、文件系统、shell、数据库或密钥。Electron 配置必须启用：

- `contextIsolation: true`
- `sandbox: true`
- `nodeIntegration: false`
- 导航和新窗口默认拒绝
- IPC 方法使用显式白名单和参数校验

所有高权限能力集中在主进程的 Agent Runtime 中。

## 5. 系统组件

### 5.1 App Shell

负责应用窗口、项目选择、全局任务状态和页面导航。主界面固定为三栏：

- 左栏：品牌、发起新任务、当前项目、任务历史、设置入口。
- 中栏：任务标题、当前模型、暂停按钮、对话、工具事件、文件差异和输入框。
- 右栏：任务状态、进度条、动态倒计时、步骤列表和最近终端输出。

窗口变窄时，右栏折叠为抽屉；左栏可收窄，但任务进度入口始终可见。

### 5.2 Task Orchestrator

Task Orchestrator 管理单个任务的完整生命周期：

`draft → planning → running → awaiting_approval | paused → running → completed | failed | canceled`

职责包括：

- 创建任务和执行上下文。
- 请求模型生成结构化任务计划。
- 保存步骤及初始时长估算。
- 调度模型请求、工具调用和重试。
- 发出可重放的任务事件。
- 处理暂停、继续、取消和应用重启后的恢复。

应用异常退出后，原本处于 `running` 的任务恢复为 `paused`，并显示“上次执行被中断”；用户明确继续后才会重新执行。

### 5.3 Model Gateway

Model Gateway 对上层提供统一流式接口：

- 输入：系统指令、任务上下文、消息、工具定义、模型配置。
- 输出：文本增量、推理状态、工具调用、用量信息、结束原因和错误。

第一版包含两种 Provider：

1. **KIMI K3 Provider**
   - 内置 Moonshot/Kimi 官方 API 配置模板。
   - 默认模型 ID 为 `kimi-k3`。
   - 用户只需录入 API Key，并可测试连接。
2. **OpenAI-Compatible Provider**
   - 用户配置名称、Base URL、API Key、模型 ID、上下文长度和可选请求头。
   - 支持兼容 Chat Completions 的流式文本与工具调用。

所有任务在启动时保存所用 Provider 与模型的快照。删除 Provider 不影响历史任务记录；正在运行的任务所使用的 Provider 不允许删除，必须先暂停或结束任务。

### 5.4 Tool Runtime

第一版提供以下工具：

- 列出目录和搜索文件。
- 读取文本文件。
- 创建或修改文本文件。
- 生成并展示文件差异。
- 运行终端命令并流式返回标准输出和错误输出。
- 停止正在运行的命令及其子进程。
- 查询 Git 状态和差异，但不自动提交、推送或创建 PR。

文件修改使用原子写入策略：先写临时文件，成功后替换目标。每次修改前保存可恢复的任务级补丁信息，使用户能查看本次任务产生的差异。

### 5.5 Permission Engine

默认采用用户确认的安全模式：

无需额外确认：

- 读取所选项目内的文件。
- 搜索所选项目。
- 修改或创建所选项目内的普通文件。
- 在所选项目目录中运行常规开发命令。

必须确认：

- 删除文件或目录。
- 访问、修改或执行所选项目目录之外的内容。
- 使用管理员权限。
- 修改系统设置、登录项或全局 shell 配置。
- 安装系统级软件或全局包。
- 运行被规则识别为破坏性或不可恢复的命令。

路径检查必须先解析符号链接和规范化路径，再判断是否位于项目根目录。模型不能通过提示文本绕过权限规则。等待确认期间，任务状态变为 `awaiting_approval`，倒计时暂停。

### 5.6 Progress Engine

进度条和倒计时基于真实步骤：

1. 规划阶段要求模型为每个步骤提供目标、完成条件和预计秒数。
2. 每个步骤的权重等于其预计时长占总预计时长的比例。
3. 已完成步骤贡献全部权重。
4. 当前步骤只根据已观察到的子事件增加进度，并在完成前最多贡献该步骤权重的 85%。
5. 剩余时间等于未完成步骤估算之和，并使用已完成步骤的“实际时间 / 预计时间”指数平滑系数动态校正。
6. 任务重规划时保存旧计划事件，并以新计划重新计算进度；已完成工作不会倒退到 0。
7. 等待用户授权、手动暂停和无网络重试等待期间暂停倒计时。
8. 估算无法可靠计算时显示“正在重新估算”，不显示虚假的精确秒数。

界面同时展示：

- 完成百分比。
- 已用时间。
- 预计剩余时间。
- 当前步骤。
- 每个步骤的状态与实际耗时。

## 6. 数据设计

SQLite 保存以下实体：

- `projects`：项目名称、规范化路径、最近打开时间。
- `tasks`：标题、项目、状态、模型快照、创建/更新时间、进度和计时字段。
- `messages`：用户、代理与系统消息。
- `steps`：步骤顺序、描述、完成条件、预计和实际时长、状态。
- `events`：追加式任务事件，包括模型增量、工具开始/结束、授权、暂停、重试和错误。
- `file_changes`：任务产生的文件路径、变更摘要和补丁。
- `providers`：Provider 类型、名称、Base URL、模型 ID、能力和密钥引用。

事件表是任务恢复和审计的事实来源。界面状态从任务快照加后续事件恢复，避免仅依赖内存状态。

API Key 不进入 SQLite、日志、任务消息、错误堆栈或导出内容。界面仅显示掩码后的末四位。

## 7. 核心交互

### 7.1 创建任务

1. 用户点击“发起新任务”。
2. 用户选择项目；已选择项目时自动沿用。
3. 用户选择模型并输入任务。
4. ZoroCoding 创建任务，进入 `planning`。
5. 计划生成后，右栏立即显示步骤、初始进度和预计时长。
6. 任务进入 `running` 并开始工具循环。

### 7.2 执行与查看

- 中栏按时间显示模型消息、文件读取、命令、差异和测试结果。
- 工具事件默认折叠摘要，用户可展开详细输出。
- 文件变更可打开统一差异视图。
- 终端输出使用固定宽度字体，保留退出码和运行时长。
- 用户可在任务运行中继续补充要求，新消息在当前安全边界内加入任务上下文。

### 7.3 暂停、取消和重试

- “暂停”停止继续调用模型，并中断当前可安全中断的命令。
- “取消”需要二次确认，保留已经产生的文件变更和事件记录。
- 失败步骤可单独重试；重试不会删除之前的失败事件。
- 用户可以从历史任务恢复对话，但不会自动重放已执行的高权限工具。

### 7.4 模型管理

设置页支持：

- 添加 KIMI 或 OpenAI 兼容 Provider。
- 编辑非敏感配置。
- 更新 API Key。
- 测试连接并展示成功、鉴权失败、网络失败或模型不存在。
- 设为默认模型。
- 删除未被运行中任务使用的 Provider。

删除操作需要确认。删除后同时删除钥匙串中的密钥项；历史任务保留 Provider 名称和模型快照，但不保留密钥。

## 8. 错误处理

### 8.1 模型错误

- `401/403`：停止自动重试，提示检查 API Key，并提供“打开模型设置”。
- `404` 或模型不存在：提示检查 Base URL 和模型 ID。
- `429`：显示限流状态，按响应头或指数退避重试，倒计时标记为重新估算。
- `5xx` 或临时网络失败：最多自动重试三次；每次重试写入事件。
- 流式响应中断：保留已收到内容，从最后一个完整工具边界恢复，不重复执行已成功的工具。

### 8.2 文件和命令错误

- 文件不存在或权限不足：记录具体路径和可操作的错误说明。
- 文件在读取后被外部修改：停止覆盖，展示冲突并要求用户选择重新读取或放弃修改。
- 命令非零退出：记录退出码和输出，由代理决定修复或向用户说明。
- 命令超时：先请求正常终止，再终止子进程组，保存最后输出。
- 项目目录被移动或删除：暂停任务并要求重新定位项目。

### 8.3 应用错误

- 未处理错误写入本地脱敏日志，不包含 API Key、环境变量值或完整私有文件内容。
- 渲染进程崩溃不会继续后台高权限任务；主进程暂停任务。
- 数据库迁移失败时以只读模式启动并提供本地备份路径，不覆盖原数据库。

## 9. 可访问性与视觉规则

- 深色左侧栏、白色工作区、浅灰右侧进度栏，荧光绿色作为唯一主要强调色。
- 不使用营销首页、装饰性卡片墙或与任务无关的指标。
- 键盘可完成创建任务、切换任务、发送消息、暂停和打开命令面板。
- 所有交互控件提供可见焦点状态和辅助技术标签。
- 状态不能只依赖颜色，必须同时显示图标或文字。
- 尊重 macOS“减少动态效果”设置。

## 10. 测试设计

### 10.1 单元测试

- Provider 请求映射、流式解析、工具调用和错误标准化。
- 任务状态机的合法与非法转换。
- 步骤权重、动态时间校正、暂停和重规划计算。
- 路径规范化、符号链接逃逸和命令风险分类。
- 密钥脱敏与日志过滤。

### 10.2 集成测试

- Renderer → preload → main 的 IPC 参数校验。
- SQLite 写入、迁移、任务恢复和事件重放。
- 使用模拟模型的完整 Agent Loop。
- 文件原子写入、冲突检测、差异生成和命令取消。
- Provider 添加、测试、更新和删除时的钥匙串联动。

### 10.3 端到端测试

自动验证以下主路径：

1. 选择临时项目。
2. 创建使用模拟模型的任务。
3. 生成计划并出现进度与倒计时。
4. 读取并修改文件。
5. 运行命令并显示输出。
6. 遇到高风险操作时暂停并等待确认。
7. 完成任务并在历史记录中恢复。
8. 添加、测试和删除自定义 Provider。

### 10.4 打包验证

- 在 Apple Silicon macOS 上安装并启动 `.dmg`。
- 验证首次项目选择、钥匙串授权、shell 启动和数据库创建。
- 验证开发构建与打包构建使用相同的权限规则。

## 11. 完成标准

第一版只有在以下条件全部满足时才视为完成：

- 用户可以选择本地项目并创建任务。
- 任务先生成可见步骤和初始时间估算。
- 进度随实际步骤事件变化，暂停和等待授权时倒计时停止。
- 模拟模型和至少一个真实 KIMI K3 配置均可完成流式对话。
- 代理可以在项目内读取、修改文件并运行终端命令。
- 高风险操作无法绕过确认。
- 用户能查看文件差异、终端输出、失败原因和最终总结。
- 任务在应用重启后可以恢复为安全的暂停状态。
- 用户可以添加、测试、编辑、设为默认和删除自定义模型 API。
- API Key 不以明文出现在数据库和日志中。
- 核心单元、集成和端到端测试通过。
- 应用可以生成可安装的 macOS `.dmg`。
