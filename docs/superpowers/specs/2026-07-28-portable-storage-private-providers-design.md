# ZoroCoding 移动硬盘锁定与私人模型配置设计

日期：2026-07-28
状态：等待用户复核

## 1. 目标

ZoroCoding 的移动硬盘版本采用“便携且关闭式”存储模式：

- 应用安装在 `/Volumes/ORICO/ZoroCoding.app`。
- 所有应用数据固定写入 `/Volumes/ORICO/ZoroCodingData/AppData`。
- 所有可执行任务的项目固定放在 `/Volumes/ORICO/ZoroCodingData/Projects`。
- 移动硬盘不可用、路径不匹配或目录不可写时停止启动或暂停任务，不回退到 Mac 内置硬盘。
- 将用户提供的私人模型账号配置导入该移动硬盘实例，但不把 API Key 写入应用包、源码、数据库明文字段、日志或任务记录。

## 2. 移动硬盘目录

固定目录布局：

```text
/Volumes/ORICO/
├── ZoroCoding.app
└── ZoroCodingData/
    ├── AppData/
    │   ├── zorocoding.sqlite
    │   ├── secrets/
    │   ├── logs/
    │   └── backups/
    └── Projects/
```

`AppData` 保存任务历史、步骤、模型元数据、加密密钥和数据库备份。AI 创建或修改的项目文件只能位于 `Projects` 下。

## 3. 路径锁定

### 3.1 启动规则

正式打包版本从正在运行的 `.app` 位置解析外置卷根目录。只有同时满足以下条件时才继续启动：

1. 应用包位于 `/Volumes/<卷名>/`。
2. 卷根目录和 `ZoroCodingData` 可写。
3. `AppData` 与 `Projects` 的规范化路径仍位于同一个外置卷。

验证失败时显示可操作的中文提示并退出，不创建内置硬盘备用目录。

开发和自动化测试通过显式测试路径运行，不改变正式版本的关闭式行为。

### 3.2 项目选择

- 项目选择器默认打开 `ZoroCodingData/Projects`。
- 用户只能选择 `Projects` 本身或其子目录。
- 选择前后都执行路径规范化和真实路径解析。
- 符号链接、路径穿越或挂载点变化导致真实路径离开 `Projects` 时拒绝选择。
- 已保存项目在任务恢复前重新校验；移动硬盘重新挂载到不同名称时不静默改写路径。

现有文件工具和终端工具继续把当前项目作为第二层权限边界，因此任何模型调用都不能访问项目之外的内容。

## 4. 数据迁移

首次启动移动硬盘版本时：

- 创建固定目录并设置仅当前用户可读写的权限。
- 可复制原本 macOS `Application Support/ZoroCoding` 中的任务和非敏感配置。
- 原目录保持不变，作为可恢复副本，不自动删除。
- 如果数据库迁移失败，移动硬盘版本以只读恢复模式启动并保留备份。

迁移完成后，后续读写只使用移动硬盘目录。

## 5. 私人模型配置

为当前移动硬盘实例导入以下 Provider：

1. Groq
2. Google Gemini
3. OpenRouter
4. Cerebras
5. SambaNova
6. Mistral
7. NVIDIA NIM
8. 智谱 BigModel

另外保留产品自带但未填写密钥的 Kimi K3 与 Ollama 模板。

每个 Provider 预置官方 Base URL。导入时优先通过认证后的模型列表接口获取当前可用模型，再按“支持对话、工具调用、代码任务、免费或试用额度优先”的规则选择默认模型。无法可靠自动选择时保留 Provider 并要求用户在设置页选择，不猜测已下线的模型 ID。

Kimi K3 固定为用户选择的默认模型。即使连接测试暂时失败，也不得静默替换默认项；界面应保留 Kimi K3 为默认并显示可操作的错误状态。其他通过测试的 Provider 作为可手动切换的备用项。

ZoroCoding 不自动跨 Provider 重试，避免免费额度耗尽后意外触发其他平台的付费调用。用户可手动切换默认模型。

## 6. 密钥安全

- 用户提供的 API Key 只用于当前实例的本地导入。
- 导入过程不生成包含明文密钥的源码、补丁、配置文件或安装资源。
- 密钥使用 Electron `safeStorage` 加密后写入 `AppData/secrets`。
- SQLite 只保存随机密钥引用和末四位掩码。
- UI、错误信息、日志、测试输出和导出内容不得显示完整密钥。
- Provider 删除时同时删除对应加密密钥文件。
- 密钥因在对话中以明文提供，交付后建议用户在各平台后台轮换；新密钥可直接在设置页更新。
- `safeStorage` 加密与当前 macOS 用户的钥匙串相关。移动硬盘换到另一台 Mac 后，可能需要重新输入密钥。

## 7. 连接测试

导入后逐个执行最小测试：

1. 校验 Base URL 和 TLS。
2. 请求模型列表；不支持列表接口时使用 Provider 推荐模型。
3. 发起最短对话请求，限制输出长度。
4. 对代码任务候选模型执行一次结构化输出或工具调用能力检查。
5. 记录成功、鉴权失败、限流、模型不可用或地区限制，不记录请求密钥。

测试不承诺 Provider 的免费资格。设置页需要标注“免费额度、地区和计费规则由服务商决定”，并提供后台入口。

## 8. 界面行为

设置页的模型卡片展示：

- Provider 名称、当前模型和 Base URL。
- 连接状态与最近测试时间。
- 密钥掩码末四位。
- “测试连接”“更新密钥”“设为默认”“删除”。
- “免费/试用/可能收费”的提示标签。

应用顶部显示当前数据位置为 `ORICO/ZoroCodingData`。路径不可用时，不允许发起新任务。

## 9. 验收标准

- 应用从 ORICO 启动后，数据库、加密密钥、日志和备份只出现在 `ZoroCodingData/AppData`。
- 项目选择器无法选择 `ZoroCodingData/Projects` 之外的目录。
- 符号链接不能绕过目录限制。
- 移动硬盘断开后，运行中的任务安全暂停，不在内置硬盘继续写入。
- 8 个私人 Provider 出现在设置页，密钥仅显示掩码。
- 源码、Git 历史、应用包、测试快照和日志中不存在用户提供的完整 API Key。
- Kimi K3 是默认 Provider；其他测试成功的免费 Provider 可由用户手动改为默认。
- Kimi K3 和 Ollama 模板仍可添加、编辑和删除。
- 原有核心链路与全部安全测试继续通过。
