# ZoroCoding 自动模型路由与快速问答设计

日期：2026-07-28
状态：用户已批准
目标版本：0.2.x

## 1. 目标

在不破坏现有项目任务链路的前提下，让 ZoroCoding 根据任务类型自动选择轻量模型或 KIMI K3，并增加不需要项目的快速问答模式。

目标行为：

- 简单问答、解释、总结、翻译、润色和简单代码说明默认使用轻量模型。
- 多文件修改、复杂调试、重构、测试、架构、绘图和视频脚本任务默认使用 KIMI K3。
- 自动分类完全在本地完成，不为分类额外调用任何模型。
- 项目内轻量任务只能读取项目，不能修改文件或运行终端。
- 快速问答不选择项目，不能读取或修改项目文件，也不能运行终端。
- 绘图和视频任务由 K3 编写并运行 SVG、Canvas、FFmpeg、Remotion、Manim 等本地脚本，不接入额外媒体生成 API。
- 模型在任务或单次快速问答开始后固定，失败时不自动切换。
- 快速问答历史保存在 ORICO，重启后可以继续查看。
- 所有新增界面遵守已批准的严格黑绿主题。

## 2. 产品模式

### 2.1 项目任务

保留原有核心链路：

> 选择项目 → 输入要求 → 本地识别任务类型 → 显示模型选择原因 → 提交任务 → AI 执行 → 查看进度与结果

项目任务分为两种执行模式：

| 执行模式 | 适用任务 | 工具权限 |
| --- | --- | --- |
| 只读问答 | 简单问答、文字、解释、翻译、润色、简单代码说明 | 只允许列出、搜索和读取已授权项目文件 |
| 完整执行 | 复杂代码、调试、重构、测试、绘图和视频脚本 | 沿用现有文件修改、终端和审批机制 |

只读问答的限制必须由主进程执行，不能只依赖提示词或隐藏按钮。

### 2.2 无项目快速问答

侧栏增加“快速问答”入口：

- 无需选择项目。
- 不接收项目 ID 或项目路径。
- 不创建文件修改记录。
- 不注册或调用文件、终端、项目选择工具。
- 使用相同的本地任务分类器选择轻量模型或 K3。
- 复杂代码可以由 K3 分析和给出代码，但不能直接落盘或运行。
- 绘图或视频请求显示“转为项目任务”操作；只有转为项目任务后，K3 才能编写和运行本地生成脚本。
- 会话和消息历史保存在 ORICO 数据库。

## 3. 模型角色

设置页增加“自动模型路由”区域：

- **轻量模型**：默认选择已配置的 Groq。
- **高级模型**：默认选择已配置的 KIMI K3。
- 两个角色都可以从已配置模型中手动更换。
- 删除正在作为路由角色的模型时，先提示用户选择替代模型。
- 路由配置只保存模型配置 ID，不保存或复制 API Key。

首次迁移规则：

1. 高级模型优先选择名称和模型类型均匹配 KIMI K3 的配置。
2. 轻量模型优先选择名称匹配 Groq 的配置。
3. 如果目标模型不存在，对应角色保持未配置，创建任务或发送快速问答前给出明确提示。
4. 不自动选择一个未确认的自定义模型作为替代。

## 4. 本地分类器

分类器是一个纯函数，不访问网络、数据库、文件系统或模型：

```ts
type TaskIntent =
  | "simple_qa"
  | "simple_text"
  | "simple_code"
  | "complex_code"
  | "media_script";

type ModelLane = "light" | "premium";
type TaskExecutionMode = "read_only" | "agentic";

interface RouteDecision {
  intent: TaskIntent;
  lane: ModelLane;
  executionMode: TaskExecutionMode;
  confidence: "high" | "medium";
  reasonCode:
    | "simple-question"
    | "text-transform"
    | "code-explanation"
    | "project-change"
    | "multi-step-code"
    | "media-generation"
    | "ambiguous-premium-default";
}
```

### 4.1 判断顺序

按以下优先级判断，命中后停止：

1. 绘图、图表、SVG、Canvas、动画、FFmpeg、Remotion、Manim、视频剪辑或视频生成脚本 → `media_script`、高级模型、完整执行。
2. 修改、实现、修复、重构、迁移、构建、部署、安装依赖、运行命令、运行测试、多文件或架构任务 → `complex_code`、高级模型、完整执行。
3. 解释代码、说明报错原因、给出小片段且没有修改或运行意图 → `simple_code`、轻量模型、只读问答。
4. 翻译、润色、改写、总结、提纲、文案 → `simple_text`、轻量模型、只读问答。
5. 一般知识、概念解释和短问答 → `simple_qa`、轻量模型、只读问答。
6. 语义不明确或同时命中轻量和复杂信号 → 高级模型、完整执行。

### 4.2 复杂度信号

以下信号提高复杂任务优先级：

- 同时出现多个动作要求。
- 明确要求读取或修改多个文件。
- 明确要求运行测试、构建、安装、部署或终端命令。
- 要求诊断现有故障并验证修复。
- 要求创建完整功能、系统、网站、应用、动画或视频。
- 提示词较长且包含验收标准、阶段或依赖关系。

提示词长度不能单独决定模型，只能作为辅助信号。

## 5. 用户可见的路由结果

项目任务输入框下方实时显示：

```text
已识别：复杂代码
将使用：KIMI K3
原因：需要修改项目并运行测试
```

模型选择控件提供：

- `自动选择（推荐）`
- 已配置模型列表

用户选择具体模型时，只覆盖模型，不覆盖安全执行模式。例如，复杂项目任务即使手动选择免费模型，仍然使用完整执行权限和现有审批规则；简单问答即使手动选择 K3，仍然保持只读。

提交请求不直接信任渲染器给出的自动路由结果。主进程使用相同的纯函数重新分类并解析模型角色，然后把最终决定写入任务快照。

任务详情持续显示：

- 识别出的任务类型。
- 自动或手动选择。
- 实际模型名称和模型 ID。
- 只读问答或完整执行模式。

## 6. 任务开始后的模型固定

- 主进程在创建任务或发送快速问答时解析一次模型。
- 项目任务把完整 provider snapshot 和 route decision 写入任务记录。
- 快速问答的每条助手回复保存实际 provider snapshot 和 route decision。
- 运行中不因超时、限流、余额不足或模型错误切换到其他模型。
- 失败时显示原模型和失败原因。
- 用户可以重试原模型，或明确选择另一个模型后重新发起。
- 不自动重复文件修改、终端命令或媒体脚本。

## 7. 主进程安全边界

### 7.1 只读项目任务

任务快照增加 `executionMode: "read_only" | "agentic"`。

`read_only` 模式：

- 允许安全地列出、搜索和读取已授权项目内文件。
- 拒绝写文件、创建文件、删除文件、移动文件和应用补丁。
- 拒绝所有终端命令。
- 拒绝任何项目边界外读取。
- 权限拒绝发生在主进程工具调用边界，并产生可见任务事件。

### 7.2 快速问答

快速问答由独立 `QuickChatService` 调用 `ModelGateway`：

- 不依赖 `AgentRuntime`。
- 不接收 `ToolRegistry`、`FileTools` 或 `ShellTool`。
- 不注册文件和终端相关 IPC。
- 只负责会话、消息、路由、模型流式输出、取消和重试。

此结构保证快速问答即使收到恶意或误导提示，也没有项目和终端能力。

## 8. 数据模型

### 8.1 路由配置

新增单行表 `model_routing_config`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER | 固定为 1 |
| `light_provider_id` | TEXT NULL | 轻量模型配置 ID |
| `premium_provider_id` | TEXT NULL | 高级模型配置 ID |
| `updated_at` | INTEGER | 更新时间 |

外键使用 `ON DELETE RESTRICT`，确保路由角色不会被无提示删除。

### 8.2 项目任务

任务记录增加：

- `route_decision_json`
- `selection_mode`，值为 `auto` 或 `manual`
- `execution_mode`，值为 `read_only` 或 `agentic`

现有 `provider_snapshot_json` 继续作为实际执行模型的不可变快照。

### 8.3 快速问答

新增表：

`quick_chat_sessions`

- `id`
- `title`
- `created_at`
- `updated_at`

`quick_chat_messages`

- `id`
- `session_id`
- `role`
- `content`
- `provider_snapshot_json`，用户消息为空，助手消息记录实际模型
- `route_decision_json`，用户消息为空，助手消息记录实际路由
- `status`
- `error_message`
- `created_at`

快速问答正文与现有任务消息一样保存在 ORICO SQLite 数据库中。API Key 仍只存在于 macOS `safeStorage` 加密的独立 secret 文件中。

## 9. IPC 与输入验证

新增 IPC 能力：

- 获取和更新模型路由配置。
- 预览本地路由决定。
- 列出、创建、重命名和删除快速问答会话。
- 列出消息。
- 发送、取消和重试快速问答。
- 订阅快速问答流式事件。

所有输入使用 Zod：

- 文本去除首尾空白并限制长度。
- provider ID 必须引用现有配置。
- 会话 ID 必须存在。
- 快速问答请求不允许携带项目 ID、路径、命令或工具定义字段。
- 自动路由由主进程重新计算。

## 10. 错误处理

- 轻量或高级角色未配置：发送前阻止，并提供“前往设置”操作。
- 路由模型已删除：数据库删除被拒绝，提示先替换路由角色。
- 模型调用失败：保存失败状态和安全错误信息，不保存密钥或原始响应头。
- ORICO 断开：沿用现有 fail-closed 行为，快速问答和项目任务都立即停止写入并要求重启。
- 快速问答取消：终止当前模型请求，保留已收到的文本并标记已取消。
- 只读任务尝试写文件或运行终端：主进程拒绝并记录“只读任务不允许此操作”。

## 11. 黑绿主题集成

新增界面只使用：

- 黑色 `#000000`
- 荧光绿 `#C9FF62`

路由标签不通过第三种颜色区分：

- 轻量模型：`○ 轻量`
- 高级模型：`◆ 高级`
- 自动选择：绿色实线边框
- 手动覆盖：绿色虚线边框
- 只读模式：`只读` 文字标签
- 完整执行：`可修改项目` 文字标签

快速问答的消息、流式输出、代码块和错误区域全部黑底绿字。

## 12. 自动验证

采用测试驱动开发，先写失败测试，再实现。

### 12.1 分类器

- 简单问答路由到轻量模型和只读模式。
- 翻译、润色和总结路由到轻量模型和只读模式。
- 简单代码解释路由到轻量模型和只读模式。
- 多文件修改、修复并测试路由到 K3 和完整执行。
- SVG、Canvas、FFmpeg 和视频任务路由到 K3 和完整执行。
- 冲突或模糊提示默认 K3。
- 分类器不调用网络、文件或模型。

### 12.2 安全

- 只读项目任务无法写文件、应用补丁或运行命令。
- 快速问答服务没有文件和终端依赖。
- 快速问答 IPC 拒绝项目 ID、路径和工具字段。
- 渲染器伪造路由决定时，主进程重新计算。
- 模型失败时不自动调用第二个 provider。

### 12.3 存储

- 路由配置迁移正确选择现有 Groq 和 KIMI K3。
- 9 个现有模型和 1 个默认模型保持不变。
- 快速问答会话和历史只写入 ORICO。
- 重启后历史恢复。
- ORICO 断开时快速问答 fail closed。
- API Key 不进入路由表、聊天表、日志或 IPC 返回。

### 12.4 用户界面

- 项目任务实时显示任务类型、模型和原因。
- 自动选择和手动覆盖都能提交。
- 快速问答无需项目即可发送。
- 快速问答显示实际使用模型。
- 媒体请求提供“转为项目任务”。
- 黑绿主题静态契约和实机 computed-style 检查继续通过。
